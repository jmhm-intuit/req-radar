# Questline 4.2 Product Model

## Core records

- **Project:** a defined outcome decomposed into milestones, workstreams, Tasks, and supporting Habits.
- **Exploration:** an uncertain question decomposed into investigation threads, Tasks, evidence, options, and decisions.
- **Task:** one concrete action that can be planned, progressed, completed, replanned, or moved to another destination.
- **Habit:** a recurring target measured within a period.
- **Note:** non-actionable information, an Idea, evidence, or a reference.

An **Activity** is a planner representation, not an additional stored record.

## Task destination

A Task has one current destination:

- Resolve — standalone practical obligation
- Project — concrete step toward a defined outcome
- Exploration — concrete step that reduces uncertainty
- Renew/Fun — intentional restoration, enjoyment, or connection

Changing destination preserves the Task identity and records the prior relationship in destination history.

## Scheduling

Scheduled, Unscheduled, and Overdue are derived scheduling states, not Task categories. Date/Replan changes scheduling. Change destination changes context.

## Review analytics

All Review components use one canonical completed-Activity event stream. The event stream provides:

- Completed totals
- Priority points
- Importance, Urgency, and type breakdowns
- Life-area ownership and shared contribution
- Big Moves
- Recovery Wins
- Project and Exploration movement
- Habit target achievement

Primary area owns progress; shared areas receive contribution; global totals count each event once.

## Review history

Weekly and monthly snapshots are generated automatically after completed periods with Activity history. Manual reflection remains optional.
